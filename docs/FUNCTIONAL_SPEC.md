# `ps_splitter` 功能规划与前置输入契约规格书（Functional Specification）

> **文档版本**：1.0.0（Milestone M1 Baseline）  
> **目标目录**：`e:\aiagent\Antigravity\ps_splitter`  
> **目标运行宿主**：Adobe Photoshop CS6 ~ CC 2025+（本地基准：Photoshop 2022 `23.5`）  
> **下游对接基准**：Esoteric Software `PhotoshopToSpine.jsx`（覆盖本地实装 `v7.04` 与上游规范 `v7.42`，兼容 Spine `Import PSD` + `SpineCompatiblePsd.jsx v1.04`）

## 1. 项目定位与职责边界

### 1.1 工具定位
`ps_splitter` 是一套面向日常 Spine 2D 角色与道具拆图生产工作流的 **Photoshop 前置辅助脚本工具集**。它严格定位于原画定稿之后、Spine 官方导出脚本（`PhotoshopToSpine.jsx`）或 Spine 4.2+ 原生 `Import PSD` 之前，解决一线美术与动画师在手工精细拆图、关节补全、图层命名规范化、PS 属性兼容预处理、换装对齐以及导出前质量把关中的高频痛点。

### 1.2 上下游生产流水线衔接

```text
[ 原画完整 PSD（合层/多草图/厚涂/含 FX 与剪贴蒙版） ]
        │
        ▼  【ps_splitter 职责域：前置拆图、补全、规范、清洗、合规准出】
  1. 保护与隔离：创建只读保护快照 SRC_BACKUP [ignore] 与参考隔离区 __REF__ [ignore]
  2. 半自动拆图：选区 Copy/Cut 路由归组 + 复合剪贴蒙版链联动提取
  3. 关节与修边：X-Ray 透视参照 + 关节外延扩边/CAF 补全 + 去杂边与 Alpha Bleed 固色
  4. 命名与层级：4 套骨骼模板增量建组 + 官方 12 标签校验 + Tag-Aware 重命名/L-R 互换 + 多皮肤克隆
  5. 定位与兼容：L/R 镜像纠偏 + Pivot 参照 + 9 宫格换装对齐 + 属性安全烘焙 + 空层/碎屑/画布清洗
  6. 准出体检：执行 R01~R10 全量前置契约检查（ERROR 阻断）+ 一键净身 -> Green Pass 通行证
        │
        ▼  【严禁越界：ps_splitter 不生成 .json 骨架、不批量切 PNG、不重写图集打包】
[ 下游 Spine 官方管线 ]
  ├─ 路径 A：运行 PhotoshopToSpine.jsx (v7.04 / v7.42+) ──▶ 导出 PNG 序列 + Spine .json
  └─ 路径 B：Spine 4.2+ Import PSD（或先经 SpineCompatiblePsd.jsx）──▶ 直接导入 .spine 工程
```

## 2. 官方 12 标签白名单规范与实战避坑指南

> **规范基准说明**：`ps_splitter` 以 Esoteric Software 上游 **`PhotoshopToSpine.jsx v7.42`** 的 **12 个官方标签**为完整规范基线，同时针对本地广泛存量使用的旧版（如本机 Photoshop 2022 附带的 **`v7.04`**，仅支持 **8 个标签**）提供显式版本兼容性校验与告警提示。

### 2.2 重要实证修正与版本兼容警示

1. **收集校验阶段严格区分小写且不 trim 括号内空格（源码实证修正）**：
   - 虽然 `PhotoshopToSpine.jsx`（v7.42 `L1960`）查找部分标签值时使用了带 `"i"` 标志的正则，但在最前段的图层收集校验阶段（v7.04 `L882-960`、v7.42 `L1303-1401`），脚本通过 `/\[([^\]]+)\]/g` 提取标签字符串后，直接进入精确小写的 `switch (tag)` 与 `startsWith(tag, ...)` 校验，且**不会去除方括号内首尾或冒号前后的空格**。
   - 因此：`[Bone]`、`[IGNORE]`、`[ bone]`、`[slot :head]` 均直接报错 `invalidTag` 中止导出；`[trim:FALSE]` 因 `!== "false"` 被悄悄当作 `trim: true` 处理。`ps_splitter` 所有标签生成、解析与体检逻辑均严格采用**全小写且禁止多余空白**标准。
2. **本地 `v7.04` 与上游 `v7.42` 版本差异警告**：
   - 本地 Photoshop 2022 (`23.5`) 附带的官方脚本为 **`v7.04`**，仅支持 **8 个标签**（`bone`, `slot`, `skin`, `folder`, `merge`, `ignore`, `path:`, `scale:`），**不支持 `overlay`、`trim`、`mesh`、`name:`**；并且 `v7.04` 不支持 `[skin]` 拼接父 `[folder]` 路径，也不识别组外 `adjustment` 与 `clipping` 层。
   - `ps_splitter` 默认以 **`v7.42` 全量 12 标签**为标准，并在标签装配 UI 及合规体检报告中针对使用 `overlay`/`trim`/`mesh`/`name:` 的图层附带 `INFO`/`WARNING` 兼容性提示，提醒仍运行 `v7.04` 的团队成员升级官方脚本或避免使用该 4 项新标签。
3. **官方脚本高频隐蔽缺陷与避坑清单**：
   - **禁止使用 `[notrim]`**：官方白名单不存在 `[notrim]`，必须使用 `[trim:false]`。
   - **严防 `[path:]` 误挂普通组**：`findTagValue("path:")` 会沿父组链向上查找（v7.04 `L129-135`，v7.42 `L364-370`），若普通父组写了 `[path:weapon]`，组内所有子层全都会落盘覆盖 `weapon.png`。
   - **严防 `[overlay]` 与 PS 混合模式混淆**：`[overlay]` 是 Spine 在导出期把图层变成下方所有图层的剪贴遮罩，既不是 `Overlay` 混合模式，也不会导出到 JSON `slot.blend`。
   - **严防 `[bone]` 顶层空像素层漂移坐标**：`[bone]` 组的坐标系由遍历到的最后一层（即 PS 图层面板中该组最顶层子图层）决定；即使该顶层是空像素层，官方脚本（v7.42 `L391-400`）仍先用它的 `(0,0)` 包围盒覆写骨骼坐标，之后才在导出期丢弃空层，导致骨骼飞到画布原点。
   - **警惕 `/.png$/` 未转义正则尾部缺陷**：官方脚本清洗名时使用 `.replace(/.png$/, "")`（v7.04 `L115`，v7.42 `L347`），其中 `.` 未转义为 `\.`，导致诸如 `item_png`、`iconApng` 会被错误截断为 `item`、`icon`！`ps_splitter` 在命名检测阶段对此类尾部模式予以预警。
   - **警惕纯标签/纯非法字符图层名静默消失**：如仅命名为 `[slot:head]`（无普通名称文本），v7.04 直接报错终止，而 v7.42（`L350`）在剥离标签后发现 `!name` 会执行 `continue` **静默丢弃整张图层**而不报错。
   - **禁止任何自造私有元数据标签**：如 `[pivot:x,y]`、`[lock]`、`[ref]` 均会触发 `invalidTag` 报错中止；所有辅助参照必须隔离在 `__REF__ [ignore]` 组内，不得向导出组名称注入非官方方括号标签。

## 3. 10 条无错消费前置输入契约（Pre-Export Input Contract, R01~R10）

为确保整理后的 PSD 交付给 `PhotoshopToSpine.jsx`（v7.04/v7.42）或 Spine `Import PSD` 时 **零报错、零静默错导、零贴图覆盖**，`ps_splitter` 定义并强制实施以下 **10 条前置输入契约（R01~R10）**，由核心引擎 `PSSplitter.Core.PreflightValidator.validateDocument()` 全量执行。

1. **痛点场景（含暗坑）**：若跳过系统规划直接编码，极易导致对 `PhotoshopToSpine.jsx` 官方标签语义理解偏差（如忽略收集阶段严格区分小写且不 trim 空格、`[mesh:target]` 完整前缀要求、`[skin:/...]` 前导 `/` 冲突、`v7.04` vs `v7.42` 版本断层）、`Core` 与 `Host` 耦合无法脱离 Photoshop 验证、以及 V1 与 V2+ 边界模糊。
2. **操作交互流程**：由 M1 团队深入调研本地 `PhotoshopToSpine.jsx`（v7.04/v7.42）与一线拆图生产痛点，编制 `docs/FUNCTIONAL_SPEC.md` 与 `docs/ARCHITECTURE.md` 并经多轮独立验证与审校冻结，作为下游 M2~M5 开发与 E2E 测试的权威依据。
3. **输入/输出与边界约束**：
   - **输入**：`ORIGINAL_REQUEST.md`、`PROJECT.md` 及官方导出脚本源码实证。
   - **输出**：`docs/FUNCTIONAL_SPEC.md` 与 `docs/ARCHITECTURE.md`。
   - **边界**：严禁在本阶段编写产品代码（`src/`）或测试代码（`tests/`），确保规划先行、接口与契约零歧义冻结。
4. **技术取舍理由**：先固化 `VirtualDoc` 快照契约、30 项 `Core` 纯 ES3 接口签名与 R01~R10 校验规则，可使 M2（`Core`）、M3（`Host`）、M4（`UI/Entries`）与独立 E2E Track 安全并行开发而不互相阻塞。
5. **优先级划分**：**文档前置（M1 交付基线）**。

#### `F-E2E` 独立客观验证与 E2E 测试体系 — **[质量保障 / 全周期]**
1. **痛点场景（含暗坑）**：ExtendScript 脚本传统上缺乏自动化回归手段，极易在中文 Windows 缺少 UTF-8 BOM 编码、无选区触发 `Error 1302`、`>= 500` 层 `rasterizeAll()` 静默失效、`node:vm` 跨 Realm 对象逃逸或 ES5+ 语法混入时出现线上崩溃。
2. **操作交互流程**：由独立于产品实现者的验证流水线基于 Node.js `v24.17.0` 原生模块执行三层测试（ES3 静态与 `#include` 闭合审计 -> `node:test` 单元测试 -> 屏蔽 ES5+ 原型的 `node:vm` Mock PS 沙箱 Tier 1-5 E2E 套件 + 独立 R01~R10 验证器），通过 `node --test` / `npm.cmd test` 一键跑通全量验证。
3. **输入/输出与边界约束**：
   - **输入**：`src/` 全量源码、测试夹具与对抗边界用例。
   - **输出**：结构化测试断言报告（全部 Tiers 1-5 零失败退出码 `0`）。
   - **边界**：严格零第三方 npm 依赖；沙箱夹具必须在沙箱 Realm 内部构造以防止外层 Node 数组原型逃逸 ES5+ 检测；测试端使用的 R01~R10 验证器独立于被测源码，防止同源盲区。
4. **技术取舍理由**：借助 Node.js `v24.17.0` 原生 `node:test` + `node:vm` 实现毫秒级零外部依赖确定性验证，无需启动重量级 Photoshop GUI 即可覆盖绝大部分逻辑与宿主陷阱契约。
5. **优先级划分**：**质量保障体系（E2E Track / M5 全量验收）**。

### 4.3 功能域一：面向精细人工拆分的半自动拆图辅助（`F1.1 ~ F1.5`）

#### `F1.1` 原稿只读快照保护组（`SRC_BACKUP [ignore]`） — **[V1 Core]**
1. **痛点场景（含暗坑）**：画师习惯在合并后的原画主层上直接用套索剪切拆件，一旦漏剪一缕发丝、剪歪边缘或后期修改造型，原稿像素已被挖空且超过历史记录步数，被迫翻找旧文件重来；若简单复制一份“原画备份”却忘打 `[ignore]`，导出时又会被当作巨大底图打进图集。
2. **操作交互流程**：
   - 运行 `00_Init_Workspace.jsx` 或在主控台点击「初始化工作区 / 创建原稿快照」；
   - 若未选中特定源层，允许一键基于当前可见/选定层复制生成快照；
   - 将副本置入文档最底层组 `SRC_BACKUP [ignore]`，自动关闭显示（`visible = false`）、开启全锁定（`allLocked = true`）并标红提示；
   - 后续返修需重取像素时，在面板点击「从备份恢复选区/无损重提取」，临时解锁备份层按当前选区复制到工作区后自动重新锁定隐藏。
3. **输入/输出与边界约束**：
   - **输入**：当前文档选中图层/组或当前可见内容。
   - **输出**：位于图层栈最底部的 `SRC_BACKUP [ignore]` 保护组。
   - **边界**：若组已存在，则在其内部新建带时间戳的子层（如 `backup_143022`），**严禁静默覆盖已有备份**；`Split_Cut`（`F1.3`）遇到 `SRC_BACKUP [ignore]` 内图层时**强制阻断剪切**，仅允许复制提取。
4. **技术取舍理由**：利用原生 `duplicate()` + `allLocked` + `[ignore]` 在单一 `.psd` 内实现原稿安全锚定，比外部多副本 `v1_bak.psd` 更符合画师单文件连续作业心流，且 `0` 导出污染。
5. **优先级划分**：**V1 Core**。

#### `F1.2` 参考草图/设计稿防导出隔离区（`__REF__ [ignore]`） — **[V1 Core]**
1. **痛点场景（含暗坑）**：三视图、动态线稿、色卡、文字注释常散落在图层树各处。画师以为“把眼睛关掉就不会导出”，但官方 `PhotoshopToSpine.jsx` 默认 `ignoreHiddenLayers = false`（v7.04 `L26` / v7.42 `L247`），运行时会自动强制 `show()` 所有未打 `[ignore]` 的隐藏层并全部导出成几十 MB 废 PNG！
2. **操作交互流程**：
   - 初始化工作区自动在图层栈最顶部建立 `__REF__ [ignore]` 组；
   - 画师选中任意参考草图/辅助层，在主控台点击「移入参考隔离区」即刻抽离至 `__REF__ [ignore]`；
   - 支持在主控台一键切换 `__REF__ [ignore]` 整组显隐与参考不透明度。
3. **输入/输出与边界约束**：
   - **输入**：1 个或多个参考图层/组。
   - **输出**：移入顶层 `__REF__ [ignore]` 组并保持命名完整。
   - **边界**：`__REF__ [ignore]` 必须位于文档顶层根目录，**严禁嵌套在任何 `[bone]`/`[slot]`/`[skin]` 导出组内部**；当源层原本位于导出组内部时，移动时同步剥离或提示其父级关系变化。
4. **技术取舍理由**：`[ignore]` 标签是官方脚本唯一无条件跳过导出的硬隔离契约（无视 `ignoreHiddenLayers` 开关），从根源彻底封堵参考图污染图集。
5. **优先级划分**：**V1 Core**。

#### `F1.3` 选区快速拆出与归组（Copy / Cut & Route） — **[V1 Core]**
1. **痛点场景（含暗坑）**：手工拆一个精细角色需要做 80~150 次重复机械动作：`Ctrl+J` 或 `Ctrl+Shift+J` -> 在几十层的树里拖拽找到对应手臂/头部组 -> 双击重命名。如果选区划偏落在纯透明区域，PS 的 `Ctrl+J` 会报错或产生隐蔽空图层；如果直接 `Ctrl+Shift+J` 剪错了备份层还会破坏原稿。
2. **操作交互流程**：
   - 美术使用套索/钢笔在源图层建立精确选区；
   - 按绑定快捷键触发 `01_Split_Copy.jsx`（保留原层完整）或 `02_Split_Cut.jsx`（从原层挖空已拆像素，直观标记进度防止漏拆）；
   - **路由与命名**：支持「极速模式（直接归入记忆的上次目标组并按顺序生成占位名如 `arm_part_03`）」与「弹窗选择目标组并输入基础名」切换。
3. **输入/输出与边界约束**：
   - **输入**：有效选区（`hasSelection === true`）+ 可编辑源图层。
   - **输出**：新拆分图层精确落入目标组内并选中。
   - **边界**：1) 无选区或选区内完全无有效像素（全透明）时**直接阻断并友好提示**，严禁生成 `isEmpty` 空层；2) 若源层位于 `SRC_BACKUP [ignore]` 或处于全锁定态，禁止 `Split_Cut`；3) 若选区跨在非像素层（如智能对象/矢量形状）执行 `Cut` 前，提示确认栅格化或自动降级为 Copy 并告警。
4. **技术取舍理由**：基于 ActionManager `CpTL`（通过拷贝的图层）与 `CtTL`（通过剪切的图层）实现毫秒级响应，包裹在 `suspendHistory` 单步事务中，支持 `Ctrl+Z` 一次撤销。
5. **优先级划分**：**V1 Core**。

#### `F1.4` 复合剪贴蒙版链联动拆出（Smart Clip-Chain Split） — **[V1 Core]**
1. **痛点场景（含暗坑）**：**一线高频实战痛点**——原画师广泛使用“1 个剪影底色层 + 3~5 个上方剪贴蒙版（阴影、二分线、高光、花纹）”来绘制角色。拆图时如果直接对底色层执行 `Ctrl+Shift+J`（剪切），上方的剪贴蒙版瞬间失去基底，整层色彩铺满全画布直接崩坏；若逐层分别框选复制再手动 `Alt+Click` 重新剪贴，操作极其繁琐且极易遗漏中间层！
2. **操作交互流程**：
   - 美术选中基底图层（或该剪贴链中的任意一个剪贴层），拉好选区后触发 `03_Split_ClipChain.jsx`；
   - 弹窗选择提取模式（或使用默认预设）：
     - **模式 A（保留结构拆出）**：在选区范围内同时裁剪提取基底 + 向上连续全部 `grouped === true` 的剪贴层，移入目标组后自动重建严格的剪贴蒙版链条关系（`grouped = true`）；
     - **模式 B（合并干净单层拆出）**：仅在副本上裁剪出选区内的基底及剪贴链，就地合并为单张干净像素层移入目标组（**原完整剪贴链保持 100% 无损**）。
3. **输入/输出与边界约束**：
   - **输入**：选区 + 属于有效剪贴蒙版链的选中层。
   - **输出**：目标组内的独立子剪贴链（模式 A）或独立合成单层（模式 B）。
   - **边界**：由 `PSSplitter.Core.ClipChainResolver.findClipChain()` 精确计算拓扑（先向下定位首个 `grouped === false` 基底，再向上连续收集紧邻 `grouped === true` 层）；若选中的是下方无基底的**悬空剪贴层**则立即阻断并提示；默认跳过链中不可见的隐藏剪贴层（可选保留）。
4. **技术取舍理由**：Photoshop 原生完全不具备“按选区联动拆分剪贴蒙版组”的能力。将拓扑分析抽离至纯 ES3 Core 层测试，Host 层通过副本交集裁剪实现原稿零损伤。
5. **优先级划分**：**V1 Core**。

#### `F1.5` 色块边界魔棒自动初拆 / 颜色区域一键分组 — **[V2+ Roadmap]**
1. **痛点场景**：针对赛璐璐/平涂风格、线稿绝对闭合的立绘，期望不手画套索即可一键按封闭色块自动切片分离为候选图层。
2. **操作交互流程**：V2+ 在 UXP 面板提供“容差滑杆 + 最小像素面积阈值 + 线稿层指定”，一键扫描连通区域并批量生成初步拆件供人工微调。
3. **输入/输出与边界约束**：仅适用于纯平涂闭合线稿，对厚涂、软边缘渐变、未闭合线稿会产生严重锯齿或碎块错误。
4. **技术取舍理由**：ExtendScript 缺乏现代高速图像像素缓冲区（Pixel Buffer）访问 API，逐点采样性能极低且精度差，规划至 V2+ 基于 UXP Imaging API 或本地算子实现。
5. **优先级划分**：**V2+ Roadmap（仅规划，不纳入 V1 运行代码）**。

### 4.4 功能域二：关节及遮挡区域的补全与边缘防护（`F2.1 ~ F2.4`）

#### `F2.1` 遮挡区域半透明参照模式（X-Ray） — **[V1 Core]**
1. **痛点场景（含暗坑）**：手臂与躯干、大腿与裙摆拆分离后，下层关节断口处于上层遮挡盲区。画师需要打开上方衣袖看位置，但完全显示又挡住下笔视野；手动改上层透明度，画完常常忘记调回 100% 或忘记解锁，导致导出变成半透明幽灵手！
2. **操作交互流程**：
   - 选中上方一个或多个遮挡参考图层/组，按快捷键触发 `06_Toggle_Ghost_Ref.jsx`；
   - **进入 X-Ray 态**：自动记录原 `opacity` 与 `allLocked` 状态，将对象设为 `35%` 不透明度、开启锁定并标记紫色外观标签；
   - 补画完成下层关节后再次选中该遮挡层（或点击面板「一键还原全部 X-Ray 层」）触发脚本，立即精准恢复原始不透明度与锁定状态。
3. **输入/输出与边界约束**：
   - **输入**：1 个或多个普通图层/图层组。
   - **输出**：可逆的半透明锁定参照态，或恢复为原始状态。
   - **边界**：原图层 `opacity` 与 `allLocked` 状态**必须持久化保存**至文档 XMP/自定义元数据或 `__REF__ [ignore]` 组内受保护状态记录节点（严禁向导出图层名注入非官方 `[...]` 标签，也不能仅依赖单次运行内存变量），以确保跨独立 `.jsx` 脚本调用以及关闭重启 PSD 后仍可无损还原并彻底清除记录，**绝不污染**导出命名校验。
4. **技术取舍理由**：原地可逆状态切换相比“复制一层半透明参考用完再删除”更加轻量直观，不会在图层树产生额外待清理的垃圾图层。
5. **优先级划分**：**V1 Core**。

#### `F2.2` 关节末端外延扩边与智能补全（Joint Extend） — **[V1 Core]**
1. **痛点场景（含暗坑）**：**非正交手绘部件关节露缝暗坑**——肩、肘、膝、颈部按斜向边缘拆开后，截面呈扁平断口，在 Spine 里骨骼只要旋转 10°~15° 立即裂开露白！而画师手动用笔刷一点点涂圆角关节耗时且容易涂出多余像素破坏周边边缘。
2. **操作交互流程**：
   - 画师用套索在需要补全的关节断口处划定局部选区（若未划选区，则针对当前层全外轮廓执行）；
   - 触发 `04_Joint_Extend.jsx`，选择扩边宽度 `N px`（默认 `12px`，范围 `2~64px`）与补全模式：
     - **模式 A（边缘像素外推垫底）**：将当前像素边界向选定断口外扩 `N px` 减去原区，抽取边缘色彩向下方垫底扩散合并；
     - **模式 B（PS 内容识别填充 CAF）**：对扩边环带区域调用原生 Content-Aware Fill 智能填充断口延伸色块与纹理。
3. **输入/输出与边界约束**：
   - **输入**：非空普通栅格层（及可选断口局部选区）。
   - **输出**：向断口方向平滑外延 `N px` 的补全图层。
   - **边界**：扩展选区严格裁限在 `originalBounds` 向外仅扩 `2*N px` 的局部包围盒内，严禁波及远端画面；遇到格子衫/复杂鳞甲等规律纹理时弹窗提醒美术做局部笔刷微调。
4. **技术取舍理由**：ES3 纯 JS 无法高速迭代图像 RGBA 缓冲区；组合 PS 原生选区扩展 + AM `contentAwareFill` 与边缘推实算法毫秒级即可完成局部非正交关节外延，零外部二进制依赖。
5. **优先级划分**：**V1 Core**。

#### `F2.3` 柔边与半透明溢色/黑边白边防护（Matte & Alpha Bleed） — **[V1 Core]**
1. **痛点场景（含暗坑）**：
   - **黑/白边问题**：从白底/黑底线稿拆件，或柔边笔刷半透明边缘残留纯黑 `(0,0,0)` / 纯白 `(255,255,255)` RGB 值，在 Spine 启用线性滤波（Linear Filtering）或 Unity PMA（预乘 Alpha）渲染时，贴图边缘出现一圈脏黑/白亮边。
   - **发光层致命暗坑**：很多批量修边脚本直接无差别对全图执行 `Remove Black Matte`，一旦遇到 `Linear Dodge`（滤色/线性减淡）叠加的黑底光效层，黑底会瞬间变成脏灰色废图！
2. **操作交互流程**：
   - 选中目标图层（支持批量选中），触发 `05_Clean_Edge_Matte.jsx` 或主控台「修边固色」；
   - 选择操作组合：
     1. **去杂边**：`Remove Black Matte`（去黑边）、`Remove White Matte`（去白边）、`Defringe (1~2px)`（去边缘色）；
     2. **Alpha Bleed 固色（Solidify）**：自动保存原图层精确 Alpha 通道为选区 -> 连续复制合并 `3~4` 次将半透明边缘真实色彩向外推实消除黑底渗色 -> 载回原 Alpha 蒙版并应用，确保轮廓 100% 不发虚不膨胀。
3. **输入/输出与边界约束**：
   - **输入**：1 个或多个普通栅格层。
   - **输出**：轮廓 Alpha 精确保持不变、半透明区 RGB 持有真实色相的干净图层。
   - **边界**：**强制防呆拦截**：自动检测并跳过非 `NORMAL` 混合模式图层（如 `LINEARDODGE`/`SCREEN`）以及带有 `[overlay]` 标签的图层，并在日志/弹窗明确警告“已跳过发光/遮罩层以防变灰”。
4. **技术取舍理由**：基于 Photoshop 原生多层叠加还原 Alpha 的 Solidify 技法 + AM 去杂边原语，无需依赖第三方 C++ 插件（如 Flaming Pear Solidify），开箱即用且完全跨平台稳定。
5. **优先级划分**：**V1 Core**。

#### `F2.4` 智能体素/AI 纹理外扩与骨骼方向感知自动补绘 — **[V2+ Roadmap]**
1. **痛点场景**：复杂蕾丝花纹、金属铠甲反光、格子布料在大面积被遮挡拆开后，普通 CAF 与边缘扩散难以凭空生成符合透视与花纹周期的完整补绘。
2. **操作交互流程**：V2+ 结合骨骼方向向量与局部纹理采样（或接入本地/Adobe Firefly Generative Fill API），沿着关节旋转延伸轴智能补全纹理。
3. **输入/输出与边界约束**：依赖现代 UXP 图像缓冲 API 或 Generative Fill 算力/联网环境，无法在离线 CS6~CC 2020 ExtendScript 下稳定运行。
4. **技术取舍理由**：受限于 V1 全版本离线 ExtendScript 宿主兼容性，划归 V2+ 演进路线。
5. **优先级划分**：**V2+ Roadmap（仅规划，不纳入 V1 运行代码）**。

### 4.5 功能域三：图层命名规范、槽位/皮肤与层级组织（`F3.1 ~ F3.5`）

#### `F3.1` 标准化角色骨骼模板与一键建组 — **[V1 Core]**
1. **痛点场景（含暗坑）**：不同美术命名的图层五花八门（`左前臂`、`armL`、`zuoshou_01`），动画师接手时需花费数小时重建 Spine 层级树；更糟的是如果脚本采用覆盖重建，会把已有拆好的部位覆盖或打乱顺序。
2. **操作交互流程**：
   - 在主控台「命名与模板」页选择预设模板：
     1. `humanoid`（标准人形：含 `root/hip/torso/head/arm_L/arm_R/leg_L/leg_R` 等完整骨骼与默认 `[slot]` 结构）；
     2. `chibi`（Q 版二头身简化关节模板）；
     3. `quadruped`（四足兽/坐骑骨骼模板，含前后肢与多节尾骨）；
     4. `portrait`（立绘/半身像差分模板，含 `face/eyes/mouth/hair_front/hair_back` 多表情槽位）；
   - 选择 L/R 后缀风格（如 `_L`/`_R`）及是否附带 `[bone]`/`[slot]` 标签 -> 点击「增量生成目录树」。
3. **输入/输出与边界约束**：
   - **输入**：`templateId` + 命名选项 + 当前 `VirtualDoc` 快照。
   - **输出**：在文档根部增量创建的标准 `LayerSet` 骨架树。
   - **边界**：**必须采用增量合并策略**（由 `SkeletonTemplates.buildHierarchyPlan()` 规划），遇到同名已存在组直接跳过并在其下补充缺失子组，**绝对禁止覆盖、清空或重排已有拆图图层**。
4. **技术取舍理由**：将 4 套骨骼拓扑与增量树 diff 算法完全封装在纯 ES3 的 `src/core/skeleton_templates.js`，可实现 100% 脱离 PS 的确定性单元测试。
5. **优先级划分**：**V1 Core**。

#### `F3.2` Spine 官方 12 标签可视化装配与校验 — **[V1 Core]**
1. **痛点场景（含暗坑）**：画师手敲标签经常拼错或踩坑：写成 `[solt]`、`[notrim]`、`[Bone]`、`[ ignore]`、`[scale]` 漏冒号、给普通图层加 `[merge]` 或 `[name:*]`、或把 `[overlay]` 当作 PS 的“叠加”混合模式。
2. **操作交互流程**：
   - 在主控台选中 PS 当前图层或组，点击「读取当前标签」即可解析显示其 `cleanName` 与已装配标签；
   - 通过可视化单选/复选与参数框装配或移除官方 **12 个标签**：`bone`, `slot`, `skin`, `folder`, `merge`, `ignore`, `overlay`, `trim`, `mesh`, `scale`, `name`, `path`；
   - 实时预览规范格式化后的完整图层名并一键应用。
3. **输入/输出与边界约束**：
   - **输入**：目标节点类型（`isGroup: boolean`）+ 标签键值对。
   - **输出**：严格全小写、括号内无多余空白、无互斥重复标签的规范名称。
   - **边界**：
     1. 当 `isGroup === false`（`ArtLayer`）时，UI 禁用 `[merge]` 与 `[name:*]`；
     2. 严禁出现 `[notrim]` 等非白名单标签；
     3. 同类互斥标签自动替换为最新值；
     4. 选择 `[overlay]` 时强制弹出功能提醒“这是 Spine 导出剪贴遮罩标签，非混合模式”；
     5. 选择 `overlay/trim/mesh/name` 时在状态栏提示“仅 `PhotoshopToSpine.jsx v7.42+` 支持，旧版 `v7.04` 会报错”。
4. **技术取舍理由**：所有解析/校验/拼装收口于 `src/core/spine_tags.js`，做到 UI 装配与预检引擎规则同源一致。
5. **优先级划分**：**V1 Core**。

#### `F3.3` Tag-Aware 批量重命名与 L/R 对称互换 — **[V1 Core]**
1. **痛点场景（含暗坑）**：复制整组左臂生成右臂后，内部十几个层级都叫 `upper_arm_L [slot:arm_L]`，手动逐个修改极易漏改导致重名覆盖；而普通批量改名脚本使用全局字符替换，会把 `[slot]` 里的字母 `l` 或 `[folder:left_arm]` 一并替换烂！
2. **操作交互流程**：
   - 选择作用域（当前选中多层 / 选中组及递归全部子层）；
   - 配置改名规则：添加前缀/后缀、数字序号递增（`sequentialStart`）、正则表达式查找替换（`regexPattern` + `regexFlags` + `regexReplace`）、或一键「L/R 对称互换」；
   - 勾选 `preserveTags`（默认开启）-> 点击「预览变更」查看 `oldName -> newName` 对比与同级重名冲突标红表 -> 确认后单步历史事务落地。
3. **输入/输出与边界约束**：
   - **输入**：目标节点集 + 重命名配置选项。
   - **输出**：`NamingEngine.batchRenamePlan()` 返回包含逐项 Diff 与 `conflicts` 的变更计划。
   - **边界**：开启 `preserveTags` 时，严格剥离保护末尾/前导 `[...]` 标签块，仅对有效名称主体执行改名与成对 `L/R` 互换（覆盖 `_L/_R`、`_l/_r`、`L_/R_`、`.L/.R`、`Left/Right`、`左/右`）；若预览存在同级重名冲突或产生非法字符（R02），阻断执行并标红提示。
4. **技术取舍理由**：`Tag-Aware` 隔离机制是区分 Spine 专用批量改名器与通用 PS 改名脚本的核心分水岭，并由 `naming_engine.js` 严格保证正则安全与 Windows 保留名过滤。
5. **优先级划分**：**V1 Core**。

#### `F3.4` 多皮肤/换装目录同构克隆 — **[V1 Core]**
1. **痛点场景（含暗坑）**：角色拥有多套皮肤（如 `skin_base`、`armor/gold`、`winter`），每套皮肤内的 `[slot]` 名称和附件占位名结构必须保持严丝合缝的一致，手建十几个子组极其容易漏槽位或拼错目录；此外不少美术会把基础皮肤命名为 `[skin:default]`，导致官方脚本直接报错崩溃。
2. **操作交互流程**：
   - 选中作为参照基准的皮肤组或部件组，在主控台点击「克隆为新皮肤」；
   - 输入目标皮肤名（支持多级目录格式，如 `armor/gold`）；
   - 选择克隆模式：「仅克隆同构空槽位/骨骼骨架」（用于画师全新绘制换装）或「完整克隆带占位图层」（用于局部改色/换贴图）；
   - 执行后自动生成 `[skin:target]` 完整层级树，并自动处理内部对应名称映射。
3. **输入/输出与边界约束**：
   - **输入**：源 `VirtualNode` 组 + 目标 `targetSkinName` + 克隆选项。
   - **输出**：由 `SkinMapper.buildSkinClonePlan()` 生成的新皮肤目录创建计划。
   - **边界**：`SkinMapper.validateSkinName()` 严格拒绝 `"default"`（不区分大小写）、前导 `/`（如 `/hero`，在 `v7.42` 必触发 `expectedAttachmentPrefix`）及含非法路径字符的名称；UI 明确提醒跨皮肤共用部件（如共用眼球、通用影子）应放置在 `[skin]` 组外部以免重复导出。
4. **技术取舍理由**：将皮肤合法性校验与同构树克隆映射置于纯逻辑层，彻底消除手工建皮漏槽与 `default` 保留字报错。
5. **优先级划分**：**V1 Core**。

#### `F3.5` 中文词库自动映射标准英文骨骼名 — **[V2+ Roadmap]**
1. **痛点场景**：外包提交的 PSD 常包含大量全中文命名（`前刘海`、`左大腿甲`、`披风下摆_1`），团队内部规范要求全英文骨骼与槽位名以便程序通过 Spine API 换装。

3. **输入/输出与边界约束**：依赖项目自定义词库与多义词消歧确认。
4. **技术取舍理由**：不同游戏项目英文命名体系差异较大，V1 通过 `F3.3` 正则替换与 `F3.1` 英文骨骼模板已可覆盖主流需求，完整词典映射归入 V2+。
5. **优先级划分**：**V2+ Roadmap（仅规划，不纳入 V1 运行代码）**。

### 4.6 功能域四：Photoshop 图层属性兼容与画布/像素清理（`F4.1 ~ F4.4`）

#### `F4.1` PS 图层属性兼容安全扁平化 — **[V1 Core]**
1. **痛点场景（含暗坑）**：
   - 智能对象、Live 文字层、矢量形状、未应用蒙版、复杂图层样式（FX）与组外悬空调整层/剪贴层，轻则导致 Spine 裁切边界算错，重则引发全局偏色或剪贴失效。
   - **一线致命暗坑**：Photoshop 在文档总图层数 **`>= 500` 层**时，官方脚本调用的全局 `rasterizeAll()` 会**静默失效**；此外原生 `rasterizeLayer(layerStyle)` 在遇到填充不透明度/混合选项时易导致样式丢失或变形。
2. **操作交互流程**：
   - 在主控台「属性兼容与清理」页勾选待处理类型（智能对象 / 文字与矢量形状 / 栅格及矢量蒙版 / FX 图层样式 / 组外悬空剪贴与调整层）；
   - 点击「执行安全扁平化」：系统强制校验是否已有 `SRC_BACKUP [ignore]` 保护快照（无快照时弹窗强制提醒），跳过 `[ignore]` 组后逐层完成安全烘焙。
3. **输入/输出与边界约束**：
   - **输入**：文档/目标范围（自动排除 `[ignore]` 组与锁定参考组）。
   - **输出**：纯净 8-bit `NORMAL` 像素图层。
   - **边界**：
     1. 严禁调用不稳定的全局 `rasterizeAll()`，统一遍历导出节点**逐层安全栅格化**；
     2. 图层样式（FX）严格采用 **`newLayerBelow` + 双选 + `merge` (`Mrg2`)** 方式烘焙（对齐 `PhotoshopToSpine.jsx` `L1879-1900`）；
     3. 检测到**组外悬空调整层或悬空剪贴层**（下方无有效实体基底或不在 `[merge]` 组内）时，提供“向下合并至基底”或“提示封装 `[merge]`”决策，禁止无脑丢弃。
4. **技术取舍理由**：逐层定向处理结合 `newLayerBelow + Mrg2` 虽然代码量略多于全局一刀切指令，但在 500+ 层重型角色 PSD 与复杂渐变描边/内发光场景下 100% 可控不丢图。
5. **优先级划分**：**V1 Core**。

#### `F4.2` 混合模式兼容性扫描与预处理 — **[V1 Core]**
1. **痛点场景（含暗坑）**：画师习惯用 `Overlay`（叠加）、`Soft Light`（柔光）、`Color Dodge`（颜色减淡）、`Multiply` 等叠加光影，但 Spine 运行时（及官方导出脚本 `L444-449`）仅原生支持 4 种：`Normal`、`Multiply`、`Screen`、`Linear Dodge (Additive)`。其余模式导出进 Spine 后会**悄无声息退化为 `Normal`**，角色瞬间变灰变脏！
2. **操作交互流程**：
   - 点击「扫描混合模式」列出所有非 `[ignore]` 可见图层中使用了不支持混合模式的清单；
   - 针对每个异常图层提供两种人工确认方案：
     - **方案 A（模式转换）**：一键转为最接近的支持模式（如 `Color Dodge`/`Vivid Light` 提示转 `Linear Dodge` 或 `Screen`）；
     - **方案 B（向下烘焙）**：若该层为附着在底色上的剪贴光影层，直接与基底实体层就地合并烘焙为纯像素结果。
3. **输入/输出与边界约束**：
   - **输入**：`VirtualDoc` 图层树。
   - **输出**：不兼容混合模式列表及用户选定的批量处理结果。
   - **边界**：**严禁未经美术确认静默篡改混合模式**，因为改变混合模式会直接改变渲染像素色相与明度。
4. **技术取舍理由**：精准映射官方脚本源码 `L188-193` / `L444-449` 逻辑，把上线前才暴露的美术色差消灭在拆图阶段。
5. **优先级划分**：**V1 Core**。

#### `F4.3` 空层/空组/碎屑清理与超画布裁切 — **[V1 Core]**
1. **痛点场景（含暗坑）**：
   - 拆图过程残留大量 `0x0` 空图层、空分组，以及套索滑手留下的 `1x1~3x3 px` 透明边缘噪点（导出一张 1024px 的大图框里就一个 2px 杂点）。
   - **瞳孔高光致命暗坑**：部分粗糙脚本一键无脑删除 `<= 4x4 px` 的小图层，直接把角色眼睛里的 `3x3 px` 瞳孔高光点、耳钉反光全删没了！
   - 此外旋转缩放过的部件常在画布 `[0,0,W,H]` 外隐藏大量看不见的废像素，导致导出尺寸畸大或边界错算。
2. **操作交互流程**：
   - 点击「扫描垃圾与越界」：
     - **空图层与空组（`isEmpty`）**：支持一键安全清理（跳过 `[ignore]` 与锁定组）；
     - **微小碎屑（`<= 4x4 px`）**：**绝不自动静默删除**！强制在列表展示尺寸、坐标与路径，支持点击高亮选中跳到画布预览，由美术手动勾选确认后才删除；
     - **超画布越界像素**：列出包围盒超出 `[0,0,W,H]` 的图层，确认无刻意保留的隐藏拉伸区域后按画布边界裁切。
3. **输入/输出与边界约束**：
   - **输入**：`VirtualDoc` 树及清理策略选项。
   - **输出**：清理结果统计与微碎屑人工确认清单。
   - **边界**：跳过 `SRC_BACKUP [ignore]`、`__REF__ [ignore]` 及锁定保护层；严禁未确认删去 `<= 4x4 px` 有像素图层。
4. **技术取舍理由**：用“空层直清 + 微碎屑预览确认”完美解决清理效率与保护瞳孔高光之间的矛盾。
5. **优先级划分**：**V1 Core**。

#### `F4.4` 文档画布冗余透明留白安全收缩（Safe Trim Canvas） — **[V1 Core]**
1. **痛点场景（含暗坑）**：原画起稿通常用 `4096x4096` 超大画布，最终拆分好的角色实际只占中间 `1200x1800` 区域，造成 PSD 文件巨大、保存卡顿、加载缓慢；若直接使用 PS `Image > Trim` 对空文档执行会直接崩溃报错，且不留安全边距可能削掉发丝半透明羽化边缘。
2. **操作交互流程**：
   - 在主控台「画布安全收缩」输入安全外扩边距（`padding`，默认 `64px`）；
   - 点击「计算并预览新画布」，系统计算所有非 `[ignore]` 可见层的联合包围盒 + `padding`，展示裁剪前后尺寸对比；
   - 确认后执行安全画布裁剪，并给出 `rulerOrigin` 偏移同步提示。
3. **输入/输出与边界约束**：
   - **输入**：可见导出层包围盒列表 + `padding`。
   - **输出**：`AlignmentMath.calcSafeCanvasBounds()` 计算后的新画布尺寸与裁剪结果。
   - **边界**：1) 无任何有效像素层时直接阻断，绝不调用空文档会崩溃的 `doc.trim(TrimType.TRANSPARENT)`；2) 作为独立手动功能提供，不放入“一键净身”自动流中以免意外改变用户习惯的标尺定位。
4. **技术取舍理由**：先在 Core 层纯数学算出联合矩形与边距并做好零面积守卫，Host 层只执行一次 `doc.crop()`，安全、精确且支持一步撤销。
5. **优先级划分**：**V1 Core**。

### 4.7 功能域五：定位对齐与多套换装/差分效率辅助（`F5.1 ~ F5.5`）

#### `F5.1` 对称中轴线、L/R 镜像克隆与偏差纠偏 — **[V1 Core]**
1. **痛点场景（含暗坑）**：正面立绘或对称配件（左右肩甲、耳朵、鞋履）手摆位置经常出现 `2~4 px` 不对称，进入 Spine 做呼吸或镜像动画时左右晃动明显；镜像复制后忘记改名后缀导致与左侧同槽位重名报错。
2. **操作交互流程**：
   - **中轴辅助线**：一键在画布中心 X（或当前选区中心 X）生成垂直参考线；
   - **镜像克隆并互换 L/R**：选中左侧件（如 `shoulder_L`），触发 `07_Mirror_LR_Swap.jsx` -> 复制图层、以中轴 X 水平翻转（`resize(-100, 100)` + 精确平移至对称坐标）、自动调用 `NamingEngine.swapLR(..., true)` 改名为 `shoulder_R`；
   - **成对偏差检测与纠偏**：选中一对 L/R 图层 -> 计算 `AlignmentMath.calcSymmetryDeviation()` 展示 `ΔX / ΔY` 像素偏差 -> 支持一键将右侧对齐至左侧精确镜像位。
3. **输入/输出与边界约束**：
   - **输入**：单侧层/组或成对 L/R 层 + 对称轴 `axisX`。
   - **输出**：镜像新层（含正确互换的命名）或偏差数值与平移修正。
   - **边界**：3/4 斜侧面透视角色左右本就不该绝对几何对称，纠偏动作仅由用户显式触发，不得自动强制执行。
4. **技术取舍理由**：`alignment_math.js` 中纯几何运算精确度误差 `< 0.5 px`，脱离 PS 可全面校验；PS 端变换配合 `swapLR` Tag-Aware 保护，一次性解决翻面与改名。
5. **优先级划分**：**V1 Core**。

#### `F5.2` 关节旋转轴参考线与十字锚点标记（Pivot Guide） — **[V1 Core]**
1. **痛点场景（含暗坑）**：美术画好分件却不知道动画师要把旋转轴放在哪里，导致关节圆弧与圆心错位旋转跳帧；或者整张图忘记设置 PS 标尺原点，导出进 Spine 后人物脚底没落在 `(0,0)` 世界原点；若直接用 `[pivot:x,y]` 写入图层名又会被官方脚本报错拒收。
2. **操作交互流程**：
   - 美术建立小选区或选中关节图层 -> 点击「标记关节十字锚点」；
   - 系统在 `__REF__ [ignore]` 隔离组内自动生成一个高精度矢量/像素十字准星层 `pivot_<layerName>`，直观标示关节点位置；
   - 同时主控台提供当前文档 `rulerOrigin`（PS 标尺原点）实时读数与一键对齐至脚底选区/参考点功能。
3. **输入/输出与边界约束**：
   - **输入**：选区中心或目标图层中心 + 当前文档 `rulerOrigin`。
   - **输出**：隔离在 `__REF__ [ignore]` 中的参照层，或更新文档标尺原点。
   - **边界**：绝不向导出图层名注入非官方标签，也绝不篡改导出层自身的像素包围盒；明确告知官方脚本建立骨骼默认位置仍取图层视觉中心，十字标记用于辅助美术扩边修圆弧与动画师对齐参照。
4. **技术取舍理由**：将参考标记严格放进 `[ignore]` 隔离区，既满足跨角色美术-动画协作定位需求，又对官方导出管线保持 100% 透明无害。
5. **优先级划分**：**V1 Core**。

#### `F5.3` 多套换装/表情差分 9 宫格同位对齐 — **[V1 Core]**
1. **痛点场景（含暗坑）**：同一 `[slot]` 下有 5 把不同武器（长剑、巨斧、法杖）或 8 种嘴型差分，如果每张切片位置没对齐（如武器没按握柄位对齐），Spine 里换皮肤时武器直接飞出角色手心；另外做共用网格（Linked Mesh）或序列帧差分时，透明裁切会造成各帧像素宽高不一致。
2. **操作交互流程**：
   - 选中同一槽位下的 2 个及以上换装/差分图层，指定第 1 层或最底层为基准层；
   - 在 9 宫格锚点选择器中点击对齐基准点（`TL/TC/TR/CL/CC/CR/BL/BC/BR`，如武器常用 `BC` 底部中心握柄位、脸部表情常用 `CC` 几何中心）；
   - 一键批量计算 `AlignmentMath.calcNineGridOffset()` 并平移全部从属层实现同位对齐；
   - **可选配套开关**：一键为所选差分层批量注入官方 `[trim:false]` 标签以锁定统一画布导出边界。
3. **输入/输出与边界约束**：
   - **输入**：`>= 2` 个同槽位层包围盒 + 9 宫格锚点枚举。
   - **输出**：高精度平移对齐结果 + 可选 `[trim:false]` 标签装配。
   - **边界**：**明确禁止使用“在图层四角点 1% 不透明度噪点”的旧时代黑科技**（会撑爆图集空间并产生线性滤波脏点），优先采用 9 宫格对齐配合官方原生 `[trim:false]`（并提示 v7.04 旧版脚本不支持 `[trim:false]`）。
4. **技术取舍理由**：数学对齐逻辑在 `alignment_math.js` 独立单测覆盖，兼顾美术直观对齐与图集空间洁净度。
5. **优先级划分**：**V1 Core**。

#### `F5.4` 高频原子入口脚本与动作快捷键套件 — **[V1 Core]**
1. **痛点场景（含暗坑）**：美术拆图是高频笔触交互（左手键盘热键 + 右手数位笔），如果每次都要去顶部菜单「文件 > 脚本 > 浏览」或反复点开关闭模态弹窗，数位笔心流将被彻底打断。
2. **操作交互流程**：
   - 一共交付 **10 个独立 `.jsx` 入口文件**（位于 `src/entries/`）：
     - **1 个主控台入口**：`src/entries/SpineSplitter_Panel.jsx`（6 大功能域分页批量管理台）；
     - **9 个高频原子快捷键入口**：`src/entries/00_Init_Workspace.jsx`、`src/entries/01_Split_Copy.jsx`、`src/entries/02_Split_Cut.jsx`、`src/entries/03_Split_ClipChain.jsx`、`src/entries/04_Joint_Extend.jsx`、`src/entries/05_Clean_Edge_Matte.jsx`、`src/entries/06_Toggle_Ghost_Ref.jsx`、`src/entries/07_Mirror_LR_Swap.jsx`、`src/entries/08_Preflight_Check.jsx`；
   - 通过 `scripts/install_ps_scripts.bat` 或 `install_ps_scripts.ps1` 部署至 PS 脚本目录后，画师按 `docs/USER_GUIDE.md` 在 PS 动作面板录制动作并绑定 `F2~F12` 快捷键，实现单键秒级拆图与补全。
3. **输入/输出与边界约束**：
   - **输入**：各独立 `.jsx` 入口触发当前 Photoshop 活跃文档上下文。
   - **输出**：单步 `suspendHistory` 事务化操作结果；无打开文档时弹出友好提示安全退出。
   - **边界**：**不交付硬编码本机路径的二进制 `.atn` 文件**（跨磁盘/跨 PS 版本必定找不到路径报错）；部署脚本绝不覆盖或删除同目录官方 `PhotoshopToSpine` 脚本。
4. **技术取舍理由**：ScriptUI 模态主控台负责低频批量统筹配置，9 个原子 `.jsx` 负责高频肌肉记忆热键，兼得功能深度与手绘流畅度。
5. **优先级划分**：**V1 Core**。

#### `F5.5` 可停靠实时交互面板（UXP）与交互式 Pivot 拖拽器 — **[V2+ Roadmap]**
1. **痛点场景**：希望有一个可常驻停靠在 Photoshop 右侧工作区的非模态面板，随着画师切换选中图层实时刷新标签状态、骨骼归属，并能在画布上可视化拖拽轴点十字标尺。
2. **操作交互流程**：V2+ 基于 Adobe UXP（React/WebComponents + `photoshop` 监听器）监听 `select`/`make`/`delete` 事件实时渲染状态，调用 `batchPlay` 下发操作。
3. **输入/输出与边界约束**：仅限 Photoshop 2021 (v22.0+) / 2022+，不支持大量游戏团队仍在使用的 CC 2018~2020。
4. **技术取舍理由**：V1 先用 ExtendScript 覆盖全版本并沉淀纯 ES3 Core 规则引擎，V2+ 无缝将 UI 外壳平滑升级至 UXP。
5. **优先级划分**：**V2+ Roadmap（仅规划，不纳入 V1 运行代码）**。

### 4.8 功能域六：导出前合规性体检与切图准备（`F6.1 ~ F6.3`）

#### `F6.1` 导出前全量合规性体检引擎（Preflight Validator） — **[V1 Core]**
1. **痛点场景（含暗坑）**：大型角色立绘跑一次 `PhotoshopToSpine.jsx` 往往需要数分钟，经常跑到一半才因某个深层重名、Windows 保留名或拼写错标签中断退出；更可怕的是跨槽位大小写碰撞、组外调整层污染、`[bone]` 顶层空层坐标漂移等问题，官方脚本**全程不报错直接静默产出废图**！
2. **操作交互流程**：
   - 拆图与整理完成后，按快捷键 `08_Preflight_Check.jsx` 或在主控台「体检与净身」页点击「运行合规体检」；
   - 引擎采集当前 `VirtualDoc` 快照并运行 `PreflightValidator.validateDocument()`，全面核查第 3 节定义的 **R01~R10 全部契约**；
   - 面板按 `ERROR`（阻断导出）、`WARNING`（高风险提示）、`INFO`（状态与版本兼容提醒）分级列出问题，展示路径、规则编号、说明与是否支持自动修复；
   - **双击定位**：在列表双击任意问题条目，立即调用 `selectLayerById(layerId)` 在 PS 画布与图层面板高亮选中该问题图层。
3. **输入/输出与边界约束**：
   - **输入**：`VirtualDoc` 快照 + 校验选项（如目标兼容版本 `v7.42` / `v7.04`）。
   - **输出**：结构化体检报告（含 `passed` 布尔门禁、`summary`、`issues[]` 与 `exportStats.caseInsensitivePaths`）。
   - **边界**：存在任意 `ERROR` 级问题时，`passed` 必须为 `false` 并明确阻断准出提示；自动跳过 `[ignore]` 组内部的命名/属性噪音（但仍校验 `[ignore]` 标签自身合法性）。
4. **技术取舍理由**：100% 规则逻辑收口在纯 ES3 的 `src/core/preflight_validator.js`，可脱离 Photoshop 用大量对抗测试集高强度验证零盲区。
5. **优先级划分**：**V1 Core**。

#### `F6.2` 导出前一键净身与准备（One-Click Sanitize & Prepare） — **[V1 Core]**
1. **痛点场景（含暗坑）**：体检发现了十几个问题（文档是 16-bit、残留空层、5 个未栅格化智能对象、2 个带 FX 图层样式、3 个未打 `[ignore]` 隐藏参考层、1 个超画布像素），逐一手动点选修复非常繁琐；若脚本直接静默删光所有隐藏层，又可能删掉画师还没决定要留的草图。
2. **操作交互流程**：
   - 体检报告界面点击「一键净身与准备」；
   - 弹出策略确认对话框，明确勾选清理项与**隐藏层处理策略**（设为 `[ignore]` 隔离 / 保持跳过 / 删除确认）及**微碎屑二次确认清单**；
   - **强制备份守卫**：若文档尚无 `SRC_BACKUP [ignore]` 快照，强制要求一键先生成快照备份或由用户显式确认继续；
   - `SanitizePlanner.buildSanitizePlan()` 生成确定性安全排序执行序列 -> `ps_sanitizer.js` 包裹在单一 `suspendHistory` 事务中按序执行：**转 8-bit RGB -> 清理空层/空组 -> 逐层属性安全扁平化（含 FX 烘焙） -> 隐藏/锁定层处理 -> 越界裁切**；
   - 清洗完成后自动触发一次复检，若 `passed === true` 则输出 **Green Pass（导出就绪通行证）**，并提示可立即运行 `PhotoshopToSpine.jsx`。
3. **输入/输出与边界约束**：
   - **输入**：`VirtualDoc` + `PreflightReport` + 用户确认后的 `SanitizePolicy`。
   - **输出**：合规整洁的 PSD 文档状态 + 复检报告。
   - **边界**：任何破坏性清洗前必须检查 `requiresBackupSnapshot`；需要人工决策的项目（如 R02 保留名改名、R05 重名冲突、R06 路径碰撞、R09 不兼容混合模式）严禁静默硬改，保留在复检清单中引导画师处理。
4. **技术取舍理由**：Planner（纯逻辑排序规划）与 Executor（PS 事务执行）分离，杜绝“先删后崩”或“先裁后丢样式”的次序事故。
5. **优先级划分**：**V1 Core**。

#### `F6.3` 多 PSD 文件夹批处理预检与无缝联动官方导出脚本 — **[V2+ Roadmap]**
1. **痛点场景**：大型换装手游项目常有 30~100 个独立换装部件/皮肤 `.psd` 文件，夜间希望批量自动执行体检、净身并直接串联调用本机 `PhotoshopToSpine.jsx` 一键输出整套贴图与 JSON。
2. **操作交互流程**：V2+ 增加文件夹批处理调度器，按清单静默开合 `.psd`，生成批量 HTML/CSV 体检汇总日志，并对通过门禁的文件自动注入参数触发官方导出。
3. **输入/输出与边界约束**：需跨文件静默处理与定位本机官方脚本版本差异，存在单文件异常弹窗阻塞批处理风险。
4. **技术取舍理由**：V1 聚焦把单文档拆图体验与体检准出精度做到 100% 稳定可靠；多文件批处理调度划入 V2+ 扩展。
5. **优先级划分**：**V2+ Roadmap（仅规划，不纳入 V1 运行代码）**。

## 5. 技术选型依据与生产部署规范

### 5.1 脚本技术方案选型对比（ExtendScript vs CEP vs UXP）

| 评估维度 | **ExtendScript (`.jsx`/`.jsxinc`) + ScriptUI + AM**<br>（**V1 选定方案**） | **CEP (HTML5/CEF + Node.js + EvalScript)**<br>（不选用） | **UXP (Modern JS + batchPlay)**<br>（**V2+ UI 升级路线**） |
|---|---|---|---|
| **Photoshop 版本覆盖** | **CS6 ~ CC 2025+**（全覆盖游戏行业存量极高的 CC 2018~2020 及 PS 2022+） | CC 2014 ~ 2024（Adobe 已官方转为维护/淘汰路线） | **仅 PS 2021 (v22.0)+**，旧版工作机完全无法运行 |
| **与官方脚本生态一致性** | **100% 同构**，与 `PhotoshopToSpine.jsx` 共享完全相同的 DOM/AM 模型与部署目录结构 | 混合双栈：面板 UI 为浏览器，核心改图层仍要通过 `CSInterface.evalScript()` 桥接 `.jsx` | 异构模型（`batchPlay` JSON 描述符），与官方 `.jsx` 无法同进程共享代码 |
| **部署门槛与团队分发** | **零编译、零签名、零注册表修改**；直接拷贝 `.jsx` 至 `Presets\Scripts\` 即可生效 | 需修改系统 `PlayerDebugMode=1` 注册表项或申请证书打包 `.zxp`，分发极易受 IT 权限拦截 | 需安装 `.ccx` 插件包或依赖 UXP Developer Tool，本地工具链要求高 |
| **快捷键融合度** | **原生完美支持**：每个原子 `.jsx` 可直接在 PS「动作 (Actions)」面板录制并绑定 `F2~F12` | 面板按钮交互为主，独立绑定全局单步热键较繁琐 | 需通过插件菜单命令映射快捷键 |
| **持久化非模态体验** | 仅支持 `dialog` 模态弹窗（配合原子 `.jsx` 双轨弥补） | 支持可停靠面板 | **原生支持现代可停靠实时面板与事件监听** |

### 5.2 核心交互架构深层决策：`Window("dialog") + 原子 .jsx` vs `Window("palette") + BridgeTalk`

在 ScriptUI 开发中，常有开发者试图使用非模态浮动面板 `new Window("palette")` 配合 `BridgeTalk` 跨引擎消息发送来实现“常驻浮动窗”。**本项目明确否决 `palette + BridgeTalk` 方案，坚定采用“ScriptUI 模态主控台 (`dialog`) + 9 个独立原子快捷键 `.jsx`”双轨制**，决定性工程依据如下：

1. **避免 `suspendHistory()` 事务失效与历史记录碎片污染**：
   - 在 Photoshop ExtendScript 中，`palette` 窗口的按钮回调与主文档操作不在同一阻塞执行上下文中；一旦通过 `BridgeTalk` 异步发送脚本字符串执行，每次按钮点击都会作为独立的顶层消息插入 PS 事件队列。
   - 若复合操作（如“复制选区 -> 扩边 -> 归组 -> 改名”）内部包含多次异步调度或与画师数位笔操作交错，**`activeDocument.suspendHistory()` 将无法可靠包裹完整事务**，导致历史面板生成大量碎片步骤（画师按一次 `Ctrl+Z` 只能退回半步，留下残缺图层，严重破坏原子撤回体验）。
   - 反之，采用 **`Window("dialog")`（低频统筹配置）+ 原子 `.jsx`（高频热键动作）**：每一次执行都在单一、同步、阻塞的 ExtendScript 调用栈内完成，能够 100% 确定性地以 `try { activeDocument.suspendHistory(title, ...); } finally { restoreRulerUnits(); }` 包裹全部底层动作，保证**一步 `Ctrl+Z` 彻底无损撤销**。
2. **杜绝 `palette` 生命周期意外销毁与跨版本焦点丢失**：Photoshop CC 2018+ 中 `Window("palette")` 若未在持久 `#targetengine` 挂载极易随主脚本结束瞬间闪退销毁，而 `#targetengine` 在多脚本共存时又容易造成全局变量状态污染；同步双轨制彻底回避此类顽疾。

### 5.3 生产部署方式与运行命令规范

1. **Photoshop 生产安装路径**：
   - 所有生产源码部署至 Photoshop 安装目录下的 **`Presets\Scripts\SpineSplitter\`**（例如 `C:\Program Files\Adobe\Adobe Photoshop 2022\Presets\Scripts\SpineSplitter\`），与官方 `Presets\Scripts\PhotoshopToSpine\` **同级共存，互不修改或覆盖官方脚本**。
   - 重启 Photoshop 后，可在「文件 > 脚本」菜单直接看到并调用 `SpineSplitter_Panel` 及 `00_Init_Workspace` ~ `08_Preflight_Check`。
2. **一键部署工具（`scripts/`）**：
   - `scripts/install_ps_scripts.bat`：Windows 批处理脚本，支持自动探测或手工指定 PS 目录，将 `src/`（`core/`、`host/`、`ui/`、`entries/`）完整拷贝至 `Presets\Scripts\SpineSplitter\`（若目标在 `Program Files` 下会提示以管理员身份运行）。
   - `scripts/install_ps_scripts.ps1`：PowerShell 部署助手，自动扫描注册表与默认目录识别本机 PS 2018–2025 多版本并同步部署。
3. **PS Actions 热键绑定方式**：
   - 按照 `docs/USER_GUIDE.md` 指引，在 PS「窗口 > 动作」新建 `SpineSplitter` 动作组，依次点击录制并从「文件 > 脚本」运行 `01_Split_Copy` ~ `08_Preflight_Check`，随后在动作属性中分配 `F2~F12` 功能键（或映射至 Wacom/Huion 数位板快捷键）。
4. **本地测试与 PowerShell 执行策略规范**：
   - 工程内所有自动化静态审计、单元测试与 Mock E2E 测试均基于本地 **Node.js `v24.17.0`**（原生 `node:test`, `node:vm`, `node:assert/strict`），**零第三方 npm 依赖**。
   - 由于 Windows PowerShell 默认执行策略（`ExecutionPolicy`）可能拦截 `npm.ps1` 及未签名 `.ps1` 脚本，文档与日常开发统一遵循以下运行规范：
     - 运行全部自动化测试：`node --test` 或 `npm.cmd test`（或 `cmd /c npm test`），避免在 PowerShell 中直接执行裸 `npm test`；
     - 运行 PowerShell 部署脚本：`powershell -ExecutionPolicy Bypass -File scripts\install_ps_scripts.ps1`，或直接右键以管理员身份运行 `scripts\install_ps_scripts.bat`。
